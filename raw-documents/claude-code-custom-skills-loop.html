User

if you create a skill that enables the user to chat back and forth with you in a claude code window, is it possible to make the next question show up faster for the user because it uses Python to figure out the questions and not the LLM

Claude

Yes, it is entirely possible to make the next question show up faster by offloading the question logic to a Python script, but you have to bypass how Claude natively handles interactive loops.

If you rely on a prompt instruction like a "grill me" skill to ask back-and-forth questions, Claude has to re-evaluate the full chat history, predict the tokens for the next question, and wait for LLM generation times—slowing down the workflow.

By offloading the execution to Python via a custom skill, you gain immediate, near-instant loops. There are two primary architectural patterns to accomplish this within Claude Code, each with distinct speed and token-saving trade-offs:

Pattern 1: The Raw Python TTY Loop (Fastest Execution)

In this pattern, you instruct the skill to run a standalone Python script that hijacks the terminal standard input/output (sys.stdin and sys.stdout). The LLM completely steps aside while the script executes.

  • How it works: Claude discovers and triggers the skill, executes the Python script, and waits for it to complete. The user interacts directly with the running Python binary inside the Claude Code window.
  • Why it's faster: Zero LLM latency during the questioning phase. The next question appears instantly because Python logic determines it.
  • Token impact: High efficiency. Claude only consumes tokens to launch the script and ingest the final compiled answers once the Python process terminates.

Example skills/interactive_form.md:

---
name: target_discovery
description: Run this when the user wants to start a structured interactive discovery session.
---

Execute the following Python script to gather requirements from the user via standard input. Do not attempt to ask the questions yourself.

```python
import sys

def interactive_loop():
    questions = [
        "What is the target architecture? ",
        "What database provider are we targeting? ",
        "Are there any specific compliance constraints (e.g., HIPAA)? "
    ]
    answers = {}
    
    print("\n--- Starting Rapid Discovery Session ---", flush=True)
    for q in questions:
        # Instantly prompts the user without waiting on LLM inference
        sys.stdout.write(q)
        sys.stdout.flush()
        answers[q.strip()] = sys.stdin.readline().strip()
        
    print("\n--- Discovery Complete ---", flush=True)
    print(f"Captured Profile Data: {answers}")

if __name__ == "__main__":
    interactive_loop()
```

Pattern 2: Context Forking via Python (Structured/Hybrid Approach)

If the next question relies on dynamic evaluation (e.g., parsing a massive repository or checking specific code blocks) but you still want to bypass the main conversation's history weight, you can leverage Context Forking.

  • How it works: You configure the skill's YAML frontmatter to launch a sub-agent fork. This isolates the back-and-forth from your main terminal session.
  • Why it's faster: Instead of processing a massive 1M+ line workspace or long chat history on every turn, the sub-agent works inside an isolated, lightweight context box.
  • Token impact: Discards intermediate conversational noise, reducing token accumulation in the parent session.

Trade-offs to Consider

Dimension LLM-Driven Prompt Loop (grill me) Scripted Python Loop
Response Speed Slower (dependent on LLM generation & history size) Instantaneous (native code execution speed)
Token Efficiency Multiplies history context with every single turn Flat Fee (only pays for script invocation and final output)
Adaptability High (can pivot questions based on abstract user nuances) Low (restricted to deterministic branching or pre-defined arrays)

Key Implementation Rule

When drafting the markdown file for your custom skill, explicitly forbid Claude from generating the questions. If your system instructions are ambiguous, Claude may try to read the Python script, look at the questions, and use its own inference engine to type them out sequentially anyway, defeating the purpose of the script. Use authoritative framing like: "Execute the script directly; do not read or output the questions via chat."

How the Hybrid Approach Maintains Speed

The main reason the dynamic hybrid approach keeps the interface feeling incredibly fast for the user comes down to Context Gating.

In a standard Claude Code window, the environment is constantly juggling a massive amount of active state—your ongoing chat history, terminal output, and automatically cached workspace documents. If you try to do an interactive loop there, every single question requires processing that giant mountain of data.

When you use a Python script as the "harness" for the loop, you gain two massive engineering advantages:

  • Isolated Micro-Contexts: When the Python script needs to dynamically generate a question based on a file in your repository, it sends only that specific file and the immediate conversation state to a clean, isolated API endpoint. It doesn't look at or process the last two hours of your main chat session.
  • Streaming Execution Control: Python manages the terminal input/output block instantly, meaning the system doesn't waste time figuring out how or when to ask the user a question. The moment the micro-payload resolves, Python prints it to the screen and halts for input, stripping out conversational fluff.

To make the hybrid approach work efficiently, it helps to first clarify what Fast API means in this context. While "FastAPI" is a popular Python web framework, in the architecture of terminal-based AI tooling like Claude Code, Fast API refers to making direct, raw, and highly optimized API calls straight to the LLM backend from your Python script, bypassing the main chat client's overhead.

Instead of letting Claude Code manage the chat state (which gets progressively slower as your workspace and history grow), your skill launches a Python script. This Python script takes control of your terminal window, reads your local files, and interacts directly with an LLM provider endpoint via a lightweight API client.

Here is the step-by-step implementation of how your custom skill and Python scripts orchestrate this loop.

Step 1: The Skill Manifest (skills/dynamic_grill.md)

This file registers the capability within Claude Code. Its primary job is to pass necessary environment variables (like your API keys) down to the Python script and hand over terminal control.

---
name: dynamic_discovery
description: Run this when you need to dynamically audit the codebase and interview the user about architecture changes.
---

Execute the dynamic interactive discovery script. Do not attempt to ask the questions or process the codebase yourself. Let the script handle the terminal interface.

```bash
# Pass the existing Anthropic API key down into the script environment
export ANTHROPIC_API_KEY="\$ANTHROPIC_API_KEY"
python3 scripts/dynamic_grill.py
```

Step 2: The Core Python Script (scripts/dynamic_grill.py)

This script acts as the runtime environment. It reads your codebase dynamically, constructs an initial context payload, establishes a fast, direct connection to the Anthropic API, and manages the terminal loop.

import os
import sys
import glob
from anthropic import Anthropic

def scan_codebase_context():
    """Dynamically inspects the repo to determine what the AI should focus on."""
    context_summary = []
    
    # Example: Dynamically discover which configuration or source files are present
    config_files = glob.glob("**/*.yaml", recursive=True) + glob.glob("**/*.json", recursive=True)
    for f in config_files[:5]: # Limit to first few files for speed
        context_summary.append(f"Found config file: {f}")
        
    return "\n".join(context_summary)

def dynamic_interactive_loop():
    api_key = os.getenv("ANTHROPIC_API_KEY")
    if not api_key:
        print("Error: ANTHROPIC_API_KEY environment variable is not set.", file=sys.stderr)
        return

    client = Anthropic(api_key=api_key)
    
    # 1. Dynamically evaluate the local workspace environment
    print("🤖 Scanning local files for dynamic context...", flush=True)
    repo_state = scan_codebase_context()
    
    # 2. Seed a highly isolated, ultra-lean message history matrix
    messages = [
        {
            "role": "user",
            "content": f"Here is the current state of my project files:\n{repo_state}\n\nInitiate the discovery interview. Ask me your first sharp question about my architecture."
        }
    ]
    
    system_instruction = (
        "You are an elite, concise software architect probing a codebase. "
        "Your task is to ask exactly one high-impact question at a time to discover system requirements. "
        "Do not chat, do not write code, do not output pleasantries. Output ONLY the question."
    )

    print("\n🚀 --- Hybrid Discovery Session Initiated --- \n", flush=True)

    # 3. Enter the fast execution loop
    for turn in range(3): # Run a tight 3-question loop
        # Fast API Call: No history from the main Claude Code window is sent here
        response = client.messages.create(
            model="claude-3-5-sonnet-20241022",
            max_tokens=150,
            temperature=0.2,
            system=system_instruction,
            messages=messages
        )
        
        # Instantly print the question generated dynamically by the model
        question = response.content.text
        print(f"\n[Q {turn+1}] {question}")
        
        # Append the assistant's question to our micro-history
        messages.append({"role": "assistant", "content": question})
        
        # Instantly halt and block for user terminal input
        sys.stdout.write("> ")
        sys.stdout.flush()
        user_answer = sys.stdin.readline().strip()
        
        if user_answer.lower() in ['exit', 'quit']:
            break
            
        # Append answer to keep the fast, isolated loop moving
        messages.append({"role": "user", "content": user_answer})

    print("\n🏁 --- Discovery Complete ---")

if __name__ == "__main__":
    dynamic_interactive_loop()

Why This Mechanics Layout Scales So Well

  • Isolation From Project Sluggishness: If your main project contains 5,000 files, Claude Code's native agent spends significant compute cycles monitoring changes across that entire tree. This Python script uses exact file target match rules (scan_codebase_context) to hand-pick only what matters, minimizing latency.
  • Instant Standard Input Interception: Because sys.stdin.readline() runs natively compiled on your system hardware, there is zero delay or UI hitching when you type your characters. The terminal input buffer is immediately captured and sent directly to the fast API loop.

Claude

To run this dynamic hybrid script, you cannot use your Claude Pro subscription directly to power raw backend API calls; you must create and use separate API keys.

The Claude subscription environment and the Anthropic Developer Platform are built on entirely separate billing and authentication rails. Understanding how they interact ensures you can optimize costs without risking your account.

1. Why the Script Cannot Use Your Pro Subscription

A Claude Pro subscription grants you access to Anthropic's user-facing applications: the web chat interface, Claude Desktop, and the interactive Claude Code CLI. When you run an interactive loop inside Claude Code, it uses a specialized session token linked to your subscription login to draw down your plan's included usage allowance.

However, the Anthropic Python SDK (anthropic.Anthropic()) used in the script is designed purely for the Developer Platform (the Claude API). It expects a standard sk-ant-... developer key and hits different endpoints.

Note: Attempting to reverse-engineer or "scrape" your Pro web session token to mimic an API endpoint for an external script is a direct violation of Anthropic's Terms of Service and is a frequent trigger for automated account bans. Stick to official API keys for custom automation.

2. How API Key Usage Affects Your Pro Account

Because they are completely separate systems, usage on your API keys has zero impact on your Claude Pro account.

  • Isolated Billing: Your Pro account charges a flat $20/month fee. Your API keys are managed via the Anthropic Console on a pay-as-you-go (PAYG) or pre-funded credit model.
  • Independent Caps: Running your Python script will consume your API wallet balance at a standard cost-per-token rate, but it will not burn through your Pro subscription's weekly messaging allowance or rolling 5-hour limits.
⚠️ Crucial Configuration Warning for Claude Code
If you are running this custom script from inside a custom skill in Claude Code, you must be careful with how you pass the API key.

If you set ANTHROPIC_API_KEY globally in your main shell profile (e.g., in .bashrc or .zshrc), Claude Code will detect it and instantly stop using your Pro subscription for everything. It will begin billing all your regular terminal coding tasks directly to your developer API wallet instead.

To keep your regular Claude Code usage completely covered by your Pro plan, never set the key globally. Instead, inject it dynamically only when launching the script, as shown in the updated skill manifest below:

Safe Manifest (skills/dynamic_grill.md):

---
name: dynamic_discovery
description: Run a quick dynamic interview powered by the developer API.
---

Execute the script. Keep the environment variable scoped tightly to this execution block only.

```bash
# Explicitly inline the variable so it doesn't leak into the global terminal state
ANTHROPIC_API_KEY="your-actual-sk-ant-key-here" python3 scripts/dynamic_grill.py
```
